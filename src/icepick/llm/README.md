# LLM Module (`icepick.llm`)

## 1. 責務 (Intent / Responsibility)
- 長大クエリから患部ASTノード（相関サブクエリなど）をピンポイントに切り出し、最小限の周辺コンテキスト（親CTE/SELECT情報、参照テーブル一覧、参照カラム一覧）を抽出する局所スライシング機能を提供します。
- LLMへのプロンプトにおけるトークン消費とハルシネーションを極小化し、対象断片の厳密な置き換えコード（` ```sql ... ``` `）のみを出力させる構造化プロンプトを生成します。
- `LLMClient` と連携し、REST API（Gemini / Vertex AI）経由での安全な部分リライトおよび AST パース・バリデーションを実現します。

## 2. 依存制約 (Dependency Boundaries)
- **`slicer.py` の依存**: `sqlglot`, `icepick.linter.base` のみ。
- **純粋性の担保**: `slicer.py` は副作用や外部I/O（ネットワークHTTP通信・ファイルアクセス）を一切行わない純粋関数・決定論的コンポーネントとして実装します。
- **ネットワークI/Oの責務分離**: HTTP通信やAPIキー・OAuth認証などのネットワークI/Oは `client.py` および `providers/` の単一責任とし、スライサーロジックとは完全に分離します。

## 3. プラガブル LLM プロバイダ構成 (Pluggable Providers)
- **委譲型アーキテクチャ**: `LLMClient` は高レベルのオーケストレーション（リライト指示プロンプトの送信、レスポンスからの SQL 抽出、sqlglot AST パース、フェイルセーフなフォールバック制御）を担当し、プロバイダ固有の認証・URL生成・HTTP通信・ヘルスチェックは `providers/` ディレクトリ内の各プロバイダ実装に委譲しています。
- **プロバイダファクトリとレジストリ**: `icepick.llm.providers` パッケージの `create_provider()` ファクトリ関数により、指定されたプロバイダ名（"gemini", "vertex" 等）と汎用オプション辞書に基づいて適切なプロバイダインスタンスが動的に生成されます。
- **動的拡張性**: `register_provider()` 関数を使用することで、既存コードを変更することなく新しいカスタムプロバイダ（OpenAI, Anthropic 等）を外部やプラグインからレジストリに追加・差し替え可能です。
- **ヘルスチェックの統合**: 各プロバイダが `health_check()` メソッドを実装しており、`ConnectionTester`（接続診断エンジン）と連携してプロアクティブな導通確認およびトラブルシューティング支援（actionable advice）を提供します。
