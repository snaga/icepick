## アーキテクチャ

### 設計方針

- 「このシステムが何を一番大事にしているか」という基本方針を言語化する
- 例: LLMコンテキストの保護 (LLM Context-Aware Design): 巨大な実データをLLMに渡さず、Context IDというハンドルでやり取りする「ハンドルベース・アーキテクチャ」の採用。
- 例: 責務の明確な分離 (Separation of Concerns):

### 全体構成図

- システムの「静的な構造」を示すために、Mermaidの図（graph TDまたはLRとsubgraph）を使って、どのコンポーネントが存在し、どこに配置され、お互いにどう繋がっているか（依存関係）を可視化する。
- コンポーネントの境界を明確にする。
- コンポーネント間の「通信（矢印）」を整理する。
- 図の説明を分かりやすく箇条書きで記載し、図の直前に配置する。

### レイヤー構造

- 各レイヤーが「何に依存していいか」を明確にする。

### 全体シーケンス図

- 代表的な処理について、コンポーネント間のインタラクションが分かるように、シーケンス図を作成する。
- コンポーネントの名称をアクターの名称と一致させる。
- コンポーネント図に出てこないアクターについては、それが判別できるように色を変えるなどの表現上の変化を加える。
- 図の説明を分かりやすく箇条書きで記載し、図の直前に配置する。

### データフロー図

- システムの「動的な動き」を示すために、Mermaidの図（flowchart LRもしくはsequenceDiagram）を使ってデータの流れをデータフロー図（DFD）として表現する。
- 一つのリクエスト（例：CSVロードやクエリ実行）に対して、データがどう変換され、どこを流れて最終的なレスポンスになるかを描く。
- 特に、データの「変換ポイント」を強調する。
- 図の説明を分かりやすく箇条書きで記載し、図の直前に配置する。

## インターフェース

- システムの外部境界（インターフェース）を、実装者にも利用者にも明確な形で定義する。
- 以下の3つのカテゴリごとにインターフェースをグルーピングして記載する。該当するものが無ければスキップしても良い。
   - 画面: Web、スマホ等のユーザーインターフェース
      - ユーザーが利用する「画面」の定義。
      - 必須項目: 画面名、概要、表示項目、入力項目（型・説明・デフォルト値）、可能なアクション、正常時の振る舞いとレスポンス、エラー時の振る舞い。
   - API: REST API / Web API / ライブラリのAPI（Python等）
      - 外部から呼び出される「関数」や「ツール」の定義。
      - 必須項目: ツール名、概要、入力パラメータ（型・説明・デフォルト値）、戻り値の構造（JSONスキーマ）、エラー時の振る舞い。
      - IPO記述: 各ツールについて「入力（Input）」「処理概要（Processing）」「出力（Output）」を箇条書きで明記すること。
   - データ: ファイル連携、公開するデータベーススキーマ等
      - システムがデータ連携・データ公開に使う「データ」の形式
      - 対象: 入力ファイル（CSV/PDF等）、設定ファイル、永続化データのスキーマ（JSON/SQL）、キャッシュ機構
      - 必須項目: フォーマット、文字コード、制約事項、保存場所。 
   - 各カテゴリごとに、「カテゴリの概要、一覧、共通設計、個別インターフェース設計（入力・処理概要・出力）」の構造で記載する。
   - 例: REST APIの場合の構成例は以下の通り。

--- 
### REST API

REST APIの役割などの概要を記載する。

#### REST API 一覧

REST API の一覧をテーブル形式で記載する。

#### REST API 共通設計

共通設計・方針を箇条書きで記載する。

##### エンドポイント /foo

各個別のインターフェースについて、入力・処理概要・出力（Input-Processing-Output: IPO）の観点で記載する。

- 入力: 入力となるパラメータを記載する。
- 処理概要: 処理の概要を記載する。
- 出力: 戻り値の型や内容を記載する。
--- 

## コンポーネント

### クラス図概要 (High-Level Overview)

- 内部の全体が把握できるクラス図を記載する。
- 図の説明を箇条書き（3～5行程度）で記載し、図の直前に配置する。

### クラス設計

- 全体構成図に出てきているコンポーネントをブレークダウンする形で記載をする。
- 全体構成図が層別に記載されている場合は、クラス設計も層別に記載する。
- 全体構成図に出てきている概念を用いて、理解しやすい適切な粒度でグルーピングする。
- グルーピングした単位で、詳細なクラス図を記載、図の説明を箇条書きで記載し、図の直前に配置する。
- 各モジュールやコンポーネントの設計の意図や責務を明確に記述する。
- 最小粒度はプログラムのメソッド、または同等の粒度とし、入力・処理概要・出力（IPO）を表形式の一覧として記述する。
